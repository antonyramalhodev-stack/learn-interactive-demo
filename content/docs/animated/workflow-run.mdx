title: Workflow run
description: An animation of jobs and steps that run in order.
---

The `WorkflowRun` element plays back a run. Each job ticks off its steps and hands over to the next job. Use it to explain a pipeline before the learner opens the real one.

<Callout title="An animation, not live data">
  The element shows the order of events from the text you give it. It doesn't read a real
  workflow run.
</Callout>

## Try it

This example uses the jobs and step names from the deploy workflow in this repository. Select **Re-run** to play it again.

<WorkflowRun
  title="Deploy to GitHub Pages"
  trigger="git push origin main"
  result="The site is live on GitHub Pages"
>{`
build: Check out the repository, Set up Node.js, Read the GitHub Pages settings, Install dependencies, Build the static site, Upload the site
deploy: Deploy to GitHub Pages
`}</WorkflowRun>

## How you write it

Write one job on each line: the job name, a colon, then the steps with commas between them.

```mdx
<WorkflowRun
  title="Deploy to GitHub Pages"
  trigger="git push origin main"
  result="The site is live on GitHub Pages"
>{`
build: Install dependencies, Build the static site
deploy: Deploy to GitHub Pages
`}</WorkflowRun>
```

## What you'll learn

By the end of this lesson, you'll be able to:

- Create a branch for your work.
- Commit a change and push the branch.
- Open a pull request for review.

## How the flow works

You make changes on a branch, then you propose them with a pull request. After review, a maintainer merges the pull request into the default branch.

<GitGraph title="From branch to merge">{`
commit main: Start from the default branch
branch update-readme from main: Create a branch
commit update-readme: Commit a change
commit update-readme: Push the branch and open a pull request
merge update-readme into main: Merge the pull request
`}</GitGraph>

## Follow the steps

<Steps>
<Step>

### Create a branch

Create a branch named `update-readme` and switch to it.

```bash tab="git switch"
git switch -c update-readme
```

```bash tab="git checkout"
git checkout -b update-readme
```

</Step>
<Step>

### Commit a change

Edit `README.md`, then stage and commit the change.

```bash
git add README.md
git commit -m "Update README"
```

</Step>
<Step>

### Push the branch

Push the branch to GitHub. The `-u` option sets the upstream branch, so later you can run `git push` with no arguments.

```bash
git push -u origin update-readme
```

</Step>
<Step>

### Open a pull request

<Tabs items={['GitHub CLI', 'Browser']}>
  <Tab value="GitHub CLI">
    Run this command in the repository folder. The `--fill` option uses your commit message for the title and description.

    ```bash
    gh pr create --fill
    ```

  </Tab>
  <Tab value="Browser">
    Go to the repository on GitHub and open a pull request for the `update-readme` branch.
  </Tab>
</Tabs>

</Step>
</Steps>

## What happens next

After you open the pull request, the review starts.

<Timeline>
  <Event icon="pull-request" color="success" title="You open the pull request" />
  <Event icon="review" color="accent" title="A reviewer reads the change">
    The reviewer can comment, approve, or request changes.
  </Event>
  <Event icon="commit" title="You push more commits">
    New commits on the branch show up in the same pull request.
  </Event>
  <Event icon="merge" color="done" title="A maintainer merges the pull request" />
</Timeline>

## Check your knowledge

<Quiz question="What does git push -u origin update-readme do?">
  <Answer feedback="A push uploads commits. The merge happens later, through the pull request.">
    It merges update-readme into the default branch.
  </Answer>
  <Answer correct feedback="The -u option links your local branch to the remote branch, so later pushes need no arguments.">
    It uploads the branch and sets it as the upstream branch.
  </Answer>
  <Answer feedback="This command uploads the branch. It does not delete anything.">
    It deletes the update-readme branch on GitHub.
  </Answer>
</Quiz>

## Review the terms

<Flashcards>
  <Flashcard term="Branch">A separate line of work in a repository.</Flashcard>
  <Flashcard term="Commit">A saved snapshot of your changes, with a message.</Flashcard>
  <Flashcard term="Upstream branch">The remote branch that your local branch tracks.</Flashcard>
  <Flashcard term="Pull request">A proposal to merge the changes from one branch into another.</Flashcard>
</Flashcards>

## Common questions

<Accordions>
  <Accordion title="What if git switch is not available?">
    Git added `git switch` in version 2.23. On an earlier version, use `git checkout -b` instead.
  </Accordion>
  <Accordion title="Do I need the GitHub CLI?">
    No. The GitHub CLI is one way to open a pull request. You can also open one in the browser.
  </Accordion>
</Accordions>

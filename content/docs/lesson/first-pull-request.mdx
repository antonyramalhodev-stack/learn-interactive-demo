## What you'll learn

By the end of this lesson, you'll be able to:

- Create a branch for your work.
- Commit a change and push the branch.
- Open a pull request for review.

## How the flow works

You make changes on a branch, then you propose them with a pull request. After review, a maintainer merges the pull request into the default branch.

## Follow the steps

<Steps>
<Step>

### Create a branch

Create a branch named `update-readme` and switch to it.

```bash tab="git switch"
git switch -c update-readme
```

```bash tab="git checkout"
git checkout -b update-readme
```

</Step>
<Step>

### Commit a change

Edit `README.md`, then stage and commit the change.

```bash
git add README.md
git commit -m "Update README"
```

</Step>
<Step>

### Push the branch

Push the branch to GitHub. The `-u` option sets the upstream branch, so later you can run `git push` with no arguments.

```bash
git push -u origin update-readme
```

</Step>
<Step>

### Open a pull request

<Tabs items={['GitHub CLI', 'Browser']}>
  <Tab value="GitHub CLI">
    Run this command in the repository folder. The `--fill` option uses your commit message for the title and description.

    ```bash
    gh pr create --fill
    ```

  </Tab>
  <Tab value="Browser">
    Go to the repository on GitHub and open a pull request for the `update-readme` branch.
  </Tab>
</Tabs>

</Step>
</Steps>

## Common questions

<Accordions>
  <Accordion title="What if git switch is not available?">
    Git added `git switch` in version 2.23. On an earlier version, use `git checkout -b` instead.
  </Accordion>
  <Accordion title="Do I need the GitHub CLI?">
    No. The GitHub CLI is one way to open a pull request. You can also open one in the browser.
  </Accordion>
</Accordions>
